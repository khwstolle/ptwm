## v1.2 (unreleased)

### Default output needs PTWM v1.2 or later

The default outputs changed format. Readers before v1.2 reject them
with an error ("not a .ptwm container" or "bad magic"); they do not
misread them.

| Output | v1.1 | v1.2 default |
|---|---|---|
| `Compressor.compress` (one tensor) | legacy container, `\x89PTWM` | compact frame, `\x89PTWS` |
| `ptwm compress model.safetensors` (one blob per tensor in a safetensors file) | legacy container per tensor, `\x89PTWM` | compact frame per tensor, `\x89PTWS` |
| multi-tensor writers, other `ptwm compress` outputs | legacy container, `\x89PTWM` | compact container, `\x89PTWC` |

The multi-tensor writers are `compress_ptwm_blob`, `write_ptwm_shard`,
`compress_safetensors_file`, the LMDB and WebDataset writers,
`_rust.compress_model` and the Rust `compress_model` with
`CompressorOptions::default()`. The other `ptwm compress` outputs are
`--mode a`, `--mode b`, the LMDB and WebDataset stores,
`--file_compression`, `--delta` and `.bin` inputs. A tensor that does
not fit the compact frame is written as a `\x89PTWC` container.

v1.2 reads every format: `\x89PTWM`, `\x89PTWX`, `\x89PTWC` and
`\x89PTWS`.

### Writing files for v1.1 readers

Write a full container in the legacy layout:

- Python, one tensor: `CompressionConfig(framing=Framing.CONTAINER,
  container_layout=ContainerLayout.LEGACY)`.
- Python, many tensors: `container_layout="legacy"` (or
  `ContainerLayout.LEGACY`) on the writers listed above.
- CLI: `ptwm compress --container-layout legacy`, with any `--mode`.
  For a `.safetensors` file without `--mode`, this also writes every
  tensor as a full `\x89PTWM` container instead of a `\x89PTWS` frame.
- Rust: `CompressorOptions { container_layout: ContainerLayout::Legacy,
  .. }`, or `ContainerWriter::new`, which always writes the legacy
  layout.

A legacy file also records the ids of the built-in codecs and
operations it uses, and each id is derived from a release version. A
v1.1 reader recognises only the ids of version 1.1.0, so legacy
writers stamp the ids of 1.1.0 (`LEGACY_BUILTIN_VERSION`) whatever
their own crate version. v1.2 readers accept the built-in ids of any
release.

### Smaller output

Non-payload bytes (everything except coded data), measured with
`python -m benchmarks.container_overhead`:

| Case | legacy layout | v1.2 default |
|---|---|---|
| one 4 KB fp32 tensor, `Compressor.compress` | 1,014 B (`\x89PTWM`) | 50 B (`\x89PTWS`) |
| one 4 KB fp32 tensor, `Framing.CONTAINER` | 1,014 B (`\x89PTWM`) | 134 B (`\x89PTWC`) |
| 64 small fp32 tensors, per tensor | 235 B (`\x89PTWM`) | 83 B (`\x89PTWC`) |

The v1.1.0 release wrote about 2.7 KB of fixed bytes for one tensor,
most of it Extension Table entries for codecs the file did not use.
Legacy containers written by v1.2 hold only the codec entries their
planes reference.

### Other changes

- Writers reject duplicate tensor names and more than 32,768 chains,
  instead of writing files whose extra entries no reader can reach.
- Readers check every count and length before they allocate, size each
  plane from the chain before decoding it, and reject a chain whose
  Source declares far more bytes than the tensor holds.
- `Format.BYTE` input: the chain's Source now declares exactly the raw
  byte count. v1.1 could declare up to 8 times more for some dtypes;
  v1.2 still decodes those files.
- `ptwm._rust.ContainerHandle` opens a container once for many
  queries and borrows `bytes` and read-only `mmap` buffers without a
  copy. `TensorIndex.names()` returns tensors in write order.
- The transcoder (`explode_ptwm` / `implode_ptwm`) writes a
  `"ptwm-manifest-c"` version 2 manifest for compact containers. The
  legacy `"ptwm-manifest"` version 1 manifest is unchanged apart from
  optional fields, and `implode_ptwm` rejects manifests with unknown
  formats, versions or fields.

The byte layouts are in
[`docs/architecture/wire-format.md`](https://github.com/khwstolle/ptwm/blob/master/docs/architecture/wire-format.md).
